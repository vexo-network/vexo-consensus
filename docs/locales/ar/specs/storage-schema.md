## واجهة Pebble الخلفية والسجلات الثنائية

الواجهة الخلفية الافتراضية هي Pebble (`github.com/cockroachdb/pebble/v2`)، وتُفتح بذاكرة تخزين مؤقت للكتل بحجم 256 MiB وmemtable بحجم 64 MiB. تُخزَّن السجلات بالترميز الثنائي القانوني لحزمة `types`: أعداد uvarint دنيا، وسلاسل بايتات وقوائم مسبوقة بطولها، والتجزئات كبايتاتها الـ 32، وقيمة اختيارية بعد بايت حضور `0` أو `1`، والحقول بترتيب البنية التي تعلنها. يرفض المفكك كل ما عدا ذلك، بما فيه البايتات الزائدة، فيُبلَّغ عن السجل التالف بدل قراءته كقيمة أخرى، ولكل سجل ترميز واحد. دليل البيانات الذي كتبه إصدار سابق (LevelDB، سجلات JSON) غير مقروء ولا يُحوَّل: يرفض Pebble فتحه بخطأ `format major version 1`. استعد مثل هذه العقدة من snapshot أو زامنها في دليل بيانات فارغ.

المعرّفات ذات الصلة:

- `pebble: database "<dir>" was written in format major version 1, which is no longer supported`

## سجل الحالة (undo log) وذاكرة الشجرة المؤقتة

سجل الحالة هو undo log لإصدارات كل مفتاح. عندما يتغير مفتاح عند ارتفاع (كتابات الكتلة عند ارتفاعها، والكتابة المباشرة (`Set` و`Delete` و`SetBatch`) بعد أول حالة مثبتة عند الارتفاع المثبت التالي) يسجل المخزن القيمة التي كانت للمفتاح قبل ذلك، بما فيها الغياب، إصدارًا للمفتاح عند ذلك الارتفاع، مرة واحدة لكل مفتاح وارتفاع؛ وتحتفظ الكتابات المباشرة السابقة للكتلة التي تثبت ارتفاعها بالإصدار الذي سجلته أولاها (يدل `hdirect` على ذلك الارتفاع). قيمة المفتاح عند ارتفاع مثبت هي القيمة التي يسجلها أدنى إصدار له فوق ذلك الارتفاع، أو قيمته الحالية إن لم يكن له إصدار. تسجيل التغيير يقرأ القيمة الحالية للمفتاح فقط ولا يقرأ سجله، والقراءة التاريخية عملية seek واحدة في إصدارات المفتاح. يحذف `PruneBelow` كل إصدار عند الارتفاع الذي يحتفظ ابتداءً منه أو تحته. وتُسجَّل إصدارات عقد الشجرة بالطريقة نفسها. تقلل بنيتان في الذاكرة عمل الشجرة لكل كتلة، ولا تُحفظ أي منهما ولا تغير أي نتيجة: ذاكرة عقد الشجرة المؤقتة التي تحمل حتى 2^18 عقدة مرمّزة من الأشجار الحالية (يحدّثها كل batch يثبّته المخزن، ويجعل generation الفردي أثناء تثبيت مثل هذا الـ batch القارئ يستخدم الذاكرة المؤقتة عند حالة snapshot الخاص به فقط)، ولكل namespace الجذر وتغييرات العقد لآخر حساب جذر، مفهرسة بذلك الـ generation وبملخص SHA-256 لكتابات الـ namespace، فيحسب app hash وstate roots والـ commit الكتابات نفسها مرة واحدة.

## ضغط WAL الخاص بالـ mempool ودفعة genesis

لا يضغط الـ commit سجل WAL الخاص بالـ mempool إلا عندما يحوي 4 MiB على الأقل وضعف ما كان يحويه بعد آخر ضغط أو فتح. لذلك يُعاد كتابة كل بايت مضاف مرة واحدة تقريبًا في المتوسط، ويبقى السجل الذي يعيد تشغيله الإقلاع ضمن ضعف المحتوى الحي أو 4 MiB. أما الضغط الصريح (`Node.Compact`، أو إقلاع يُسقط معاملات معادة يرفضها التطبيق) فيعيد كتابته دائمًا. يكتب `InitChain` حالة genesis لكل الوحدات دفعة واحدة، فيكلّف genesis كثير الحسابات كتابة دائمة واحدة، ولا يترك genesis فاشل شيئًا في المخزن.

## براهين النهائية في دفعة الالتزام والإزالة المؤجلة من mempool

يكتب مسار الالتزام في العقدة finality proofs التي يكملها QC الكتلة في دفعة block/state/app-write نفسها (`CommitBlockStateWithWrites` يأخذها وسيطًا أخيرًا)، فيكلّف الالتزام كتابة durable واحدة بدل كتابة إضافية لكل proof. أما proof الذي سيرفضه store فيُستبعد من الدفعة وتحفظه خطوة ما بعد الالتزام التي تبلّغ عن الفشل. يزيل الالتزام معاملاته من pool ويضع سجل الإزالة في الطابور دون انتظار sync الخاص به. ينتظر الالتزام التالي حتى يصبح ذلك السجل durable قبل تنفيذ كتلته، لأن إعادة التشغيل تعيد الإزالة لآخر كتلة ملتزمة فقط. وغالبًا ما يشارك السجل sync قبولٍ لاحق.

## التجزئة المؤجلة لـ state tree

يؤجل حساب state tree التجزئة: يعلّم كل write الأنصاف التي غيّرها، ويُجزّأ كل node متغيّر مرة واحدة من الأسفل إلى الأعلى عند طلب root أو proof أو التغييرات. وهكذا تُجزّأ nodes القريبة من root، التي يعيد كل write في الكتلة كتابتها، مرة واحدة لكل كتلة بدل مرة لكل write. والتجزئات وnodes وroots هي نفسها كما لو جُزّئت عند كل write.

## المزامنة الدورية لـ mempool WAL

يكتب mempool WAL كل تغيير في log ويزامنه كل 100 ms (`walSyncInterval`). ينتظر القبول الكتابة لا المزامنة. يحتفظ انهيار العملية بكل سجل، ويفقد انهيار الجهاز على الأكثر قبولات الفترة الأخيرة التي يعيد عملاؤها إرسالها. يُزامَن سجل إزالة الكتلة الملتزمة قبل الالتزام التالي (`WaitDurable`).

## إعادة استخدام القراءات في السجل

يسجّل الالتزام القيمة السابقة لكل key متغيّر بوصفها version، وغالبًا دون قراءتها من جديد: يتذكر store القيم التي قرأها `Get` منذ آخر التزام لـ batch، حتى 2^16، لأن تنفيذ الكتلة يقرأ معظم keys التي يغيّرها. لا تُستخدم القيمة إلا إذا لم يُلتزم أي batch منذ قراءتها، فهي القيمة الحالية؛ أما key الغائب فلا يُتذكر ويُقرأ.

## إصدارات nodes في state tree

تُخزَّن nodes الشجرة حسب الإصدار ولا يعيد أي ارتفاع لاحق كتابتها. يكتب الـ batch كل node يغيّره تحت `tree: | namespace | height | node key`، ويخزّن الـ node الداخلي إصدارات نصفيه، فيُعثر على كل node من أصله. يعلّم root record (`troot:`) كل ارتفاع تغيّرت فيه الشجرة، وتُقرأ شجرة أي ارتفاع من آخر root record عنده أو تحته. يبقى الـ node المستبدَل للارتفاعات الأدنى ويُدرج في orphan list للارتفاع الذي استبدله (`torph:`، واحدة لكل batch)، ويحذفها `PruneBelow`. ولأن الإصدارات تتزايد فقط، لا تتبعثر كتابات الكتلة بين keys الموجودة، فتصغر عمليات flush وcompaction في Pebble. ولفهرس إصدارات keys (`hidx:`) أيضًا مدخل واحد لكل batch.

المعرّفات ذات الصلة:

- `troot: | namespace | height`
- `torph: | height | first entry`
- `hidx: | height | first group`

## nodes مفكوكة الترميز في الذاكرة المؤقتة

تحتفظ ذاكرة nodes المؤقتة بما يصل إلى 2^18 من nodes الأشجار الحالية مفكوكة الترميز مع إصدارات نصفيها، فلا تفك القراءة ترميزًا ولا تحجز ذاكرة.
